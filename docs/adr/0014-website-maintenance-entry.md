# 网站维护入口与 GitHub 推送资料

## 状态

已接受，2026-11-26，用户确认实施。补充 ADR 0010、0012；替代复制资料必须先关联主要仓库、且仅使用仓库所属账号的限制。

## 决策

GitHub 默认 Token 属于账号，使用现有加密凭据表；账号编辑直接提供密码型 Token 输入框，留空保留默认凭据。邮箱使用同一账号的完整登录邮箱。GitHub 账号仅含 PAT 的旧备注迁入加密默认凭据并清空；已有不同默认 Token 时保留双方并提示冲突。普通账号接口与便携备份不返回旧备注中的纯 PAT。

推送地址属于网站，保存在 `github_push_url`；留空时兼容主要代码仓库资源地址。该字段表示维护目的地，不新增或推断实际资源、仓库账号或托管关系。复制时直接网站 GitHub 账号优先于主要仓库所属账号；多个直接 GitHub 账号时要求明确选择，避免复制错凭据。

操作列优先复制 GitHub 推送资料，四行格式为“地址：”“Token：”“Email：”及“最后将整站所有的修正Github推送,包含但不限于当前对话;”。仓库 HTTPS 地址统一补 `.git`。缺失资料显示具体错误并进入部署设置，不再因未建仓库资源而长期禁用。

没有 GitHub 配置且为 WordPress 时，操作列使用新标签页登录链接。每站 `wp_login_url` 支持不含内嵌账号密码的完整 HTTP/HTTPS 自定义地址；留空为主域名的 `/safelogin`。打开登录页不自动提交登录。其他网站保留维护配置入口。单站分析及多选分析不包含凭据，保持原有行为。

两个网站字段由 v1.29 迁移增加，便携备份沿用格式版本 1 的可选字段。必须先迁移目标数据库，再发布依赖字段的代码；旧 Token 在账号页加载或复制时由登录保护的接口迁移，不在 SQL 中写入明文密钥。
