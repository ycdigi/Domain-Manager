## 部署与 GitHub

一个网站可以同时关联多个资源。每个用途最多一个主要资源；不同用途互不覆盖。

```text
网站 A
├── 托管 → SiteGround 账号 → 主机资源 → IP
├── 代码仓库 → GitHub 仓库 → 凭据账号 → Email + 默认 Token
└── DNS/CDN → Cloudflare 账号 → Zone
```

Cloudflare 托管未关联 GitHub 时提示补充，允许保存。仅使用 Cloudflare DNS 不推断托管关系。虚拟主机上的 WordPress 网站无需 GitHub。

GitHub 仓库可以属于组织，关联账号表示访问凭据账号；不根据仓库 owner 推断登录账号。每账号最多一个默认 Token；多个网站自动共用，更新邮箱或默认 Token 后立即用于下一次复制。

点击复制资料时才读取和解密 Token，格式：

```text
域名：example.com

Github地址：https://github.com/owner/repository
Github Email：user@example.com
Github Token：账号默认 Token
```

资料缺失、过期或停用凭据、解密失败与剪贴板失败会明确提示。普通列表、Excel、JSON 不包含完整 Token。

## Favicon 本地化

图片保存到本系统数据库，跨电脑复用；目前支持 PNG、ICO、JPEG、GIF、WebP。SVG 不直接保存或执行，没有可用位图时显示占位。

- 新建网站、域名变动后后台尝试获取，监控 Worker 每分钟补一个缺失主域名缓存。
- 获取网页声明图标，失败尝试 `/favicon.ico`，单图最多 256 KiB，总超时 10 秒，每请求最多 3 次跳转。
- 获取地址限 HTTPS、公共主机，检查 DNS A/AAAA 地址并拒绝私有地址。
- 成功缓存持续复用；详情可主动刷新。失败保留旧成功图片，24 小时后可再由后台尝试。
- 列表 GET 只读取本站缓存，不发起外站获取。图标接口需要登录。
- 监控 Worker 必须升级才会补齐旧站缓存；图标抓取与 HTTP 监控状态独立。

## 数据库与迁移

完整 ER 图和数据字典见 [database-structure.md](database-structure.md)。

初始化模型的 22 张业务表保留，新增 `domain_favicons`，共 23 张。生产库另有空的历史表 `alertcfg`，本次保留，因此生产库业务及历史表共 24 张，不计 Cloudflare / SQLite 内部表。

升级 v1.23 数据库使用 `schema-migration-v1.24.0.sql`；新数据库使用 `schema.sql`。执行迁移前先备份，迁移后再部署 Pages 和监控 Worker。2026-11-21 已先导出生产库备份、在副本上演练，再完成线上迁移。网站 120 个、域名 120 个、资源关联 15 条均保留；外键、数量别名、电脑迁移、唯一索引和同步触发器检查通过。监控检查记录持续由原有巡检器写入。

- 数量复制到通用字段，旧字段由存储触发器同步；同一请求新旧值冲突时报错。
- 网站电脑从主域名复制，其他域名旧电脑字段留存但不再用于当前界面。
- 可判断的资源用途转换为标准用途；同资源多条冲突旧关系保留供详情核对，不删除历史备注。
- GitHub / Cloudflare 品牌可确定，虚拟主机与 VPS 品牌需人工补充。
- 只有一个有效未到期 Token 时设为默认；多个时需指定。
- 经营场景、历史复盘原文保留，新复盘只汇总阶段及通用内容数量。
- Excel / JSON 支持新字段；图标可重新获取，不加入普通备份；加密凭据需完整数据库备份及独立保存加密密钥。
