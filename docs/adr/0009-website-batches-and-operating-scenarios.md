# 网站批次与经营场景分离网站事实和经验复盘

## 状态

已接受

## 背景

网站组合需要同时回答两个问题：当前哪些事项需要管理者行动，以及同一轮导入或经营实验中的网站结果有什么共同规律。现有网站阶段、技术栈、网站类型和网站归属关系无法表达一轮批量动作，也无法为 Astro、WordPress 等技术栈选择不同的关注指标。

## 决策

增加独立的网站批次模型。批次与网站通过多对多成员关系连接，成员加入和移出历史保留；批次记录来源、目标、假设、状态、结论和下一步。批次状态由管理者推进，只有显式请求复盘时才进入待复盘；复盘保存轻量汇总快照，不复制完整网站资料。有成员历史或复盘记录的批次只能归档。

增加可为空的经营场景。经营场景属于网站当前工作上下文，不替代技术栈、网站类型或网站阶段。第一阶段使用固定场景模板并允许自定义名称，采用固定页面数及 WordPress 内容数量字段；内容规模由人工或现有 API/AI 工作流回写，不自动抓取 sitemap 或页面。

侧边栏以待处理、批次和网站组合为主要工作入口，管理类资源集中在管理区域。待处理只汇总明确行动，资料缺失作为独立提示。

## 取舍

多对多批次关系可以表达一个网站先后参与不同实验，代价是需要成员历史和导入映射。轻量快照可以比较批次而不复制完整网站记录，代价是复盘比较范围由固定汇总字段决定。固定场景字段保持校验、导入和界面简单，未来只有出现多个无法用固定字段表达的场景时再评估通用指标表。
