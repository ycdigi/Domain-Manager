# 阶段与新站分类修正

日期：2026-11-26。

## 根因与影响范围

阶段选项曾分别写在总表、详情、批量设置、批次页、API 校验、类型及 SQL 排序中，数据库也只接受旧的五个阶段。只改一个下拉框会继续导致其他入口遗漏或保存失败。现统一使用共享阶段定义，并以 v1.30 扩展数据库约束。

新站原先是独立分类，但总表没有常驻标识和完整筛选入口；普通站 URL 条件也被当作新站。现显示新站文字，支持新站/普通站筛选、与阶段组合、刷新保留条件和清除条件。分析复制同步输出新站分类，不把新站加入阶段枚举。

复查自动判定时发现 JavaScript 月份计算在月末会溢出到下个月；现以目标月末截断，校验实际日历日期，并保留手动覆盖优先规则。

## 发布顺序

1. 确认生产数据库 `domains-db` / `92f8fb6b-9bde-4c9c-a3df-446834e00d8e`，导出完整备份。
2. 对备份副本演练 `schema-migration-v1.30.0.sql`，核对各表数据、网站外键/触发器/序列和完整性。
3. 确认旧阶段列尚未升级后执行 v1.30；该 ALTER 迁移只执行一次。
4. 推送 `main`，确认 Cloudflare 对应提交的生产部署成功。
5. 检查线上阶段选项及新站筛选；真实线上修改与恢复结果须单独记录，不以 fixture 浏览器测试替代。
