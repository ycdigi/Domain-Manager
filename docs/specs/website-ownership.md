# 网站归属关系与组合筛选功能规格

日期：2026-11-06。功能范围与以下两个测试边界均已由用户确认。本文整理已确认的需求、现有实现及架构决策，不新增业务范围。

发布状态：已配置发布到 GitHub 仓库 `ycdigi/Domain-Manager` Issues，`ready-for-agent` 标签已创建。仓库 Issues 尚未启用；当前 GitHub CLI 令牌在修改仓库设置时返回 403（权限不足），因此规格尚未发布为外部事项。

## Problem Statement

网站管理者同时运营自己的推广与 Google AdSense 收益网站，也为企业客户提供网站服务，需要在同一个网站台账中区分两种业务关系。

现有技术栈分类回答的是网站采用 WordPress、Astro、Next.js 还是其他技术；网站类型回答的是网站主要内容或功能属于计算器、资讯站还是其他。两者均不能表达网站由管理者自营还是为企业客户提供服务。将企业客户网站混入技术栈会丢失独立筛选建站技术的能力，也无法清楚解释分类后的概览数字。

## Solution

新增独立的“网站归属关系”，单选“未分类”“自营网站”“企业客户网站”。自营网站是管理者自己运营的网站，包含推广或 AdSense 变现业务；企业客户网站是管理者为企业客户提供服务的网站；未分类表示尚未确定归属关系。

新增网站默认自营网站，旧网站升级后统一为自营网站。新增和编辑表单都可以设置归属，列表支持直接修改，详情展示归属。

导航将网站归属与技术栈分组展示，两组条件共同生效。网站级概览随两组筛选变化；账号累计收入与基础设施总量保持全局口径并明确标注。导入、导出和 AI 同步保留归属信息。

## User Stories

1. 作为网站管理者，我希望区分自营网站与企业客户网站，以便分别查看自己的运营业务与企业客户服务业务。
2. 作为网站管理者，我希望每个网站只选择一种归属关系，以便分类清晰且没有重叠归属。
3. 作为网站管理者，我希望尚未确定归属的网站可以选择未分类，以便不被迫作出不准确的归属判断。
4. 作为网站管理者，我希望归属独立于技术栈和网站类型，以便企业客户网站也能记录 WordPress 技术栈和计算器等网站类型。
5. 作为网站管理者，我希望新增网站默认自营网站，以便减少录入自己运营网站时的操作。
6. 作为网站管理者，我希望新增时能够改选企业客户网站或未分类，以便准确录入不同归属的网站。
7. 作为网站管理者，我希望旧网站升级后统一归为自营网站，以便从已确认的初始归属开始整理台账。
8. 作为网站管理者，我希望在编辑表单中修改归属，以便维护网站业务关系的变化。
9. 作为网站管理者，我希望列表展示归属，以便浏览台账时直接识别网站的业务关系。
10. 作为网站管理者，我希望在列表中逐个切换归属，以便减少打开完整编辑表单的操作。
11. 作为网站管理者，我希望详情展示归属，以便查看网站资料时核对其业务关系。
12. 作为网站管理者，我希望导航中有独立的网站归属分组，以便直接选择全部归属、自营网站、企业客户网站或未分类。
13. 作为网站管理者，我希望归属与技术栈条件同时筛选，以便找到企业客户网站中的 WordPress 网站等具体组合。
14. 作为网站管理者，我希望切换一个筛选分组时保留另一组选择，以便逐步缩小范围。
15. 作为网站管理者，我希望首次没有筛选条件时显示全部归属与全部技术栈，以便先看到完整台账。
16. 作为网站管理者，我希望导航数量按另一组筛选计算，以便知道切换到某个分类后能看到多少网站。
17. 作为网站管理者，我希望搜索进一步缩小列表但不改变导航数量或概览，以便区分搜索结果与归属、技术栈范围的统计。
18. 作为网站管理者，我希望网站数量、到期、SEO、优秀网站和日点击概览随归属与技术栈筛选，以便查看当前范围的网站运营情况。
19. 作为网站管理者，我希望概览明确显示统计范围，以便理解每个数字所代表的网站集合。
20. 作为网站管理者，我希望账号累计收入与基础设施总量明确标为全局，以便避免将共享账号或资源的总量误认为筛选内网站的专属数据。
21. 作为网站管理者，我希望刷新、从详情返回或使用浏览器前进后退时恢复筛选，以便继续原来的查看任务。
22. 作为网站管理者，我希望新增始终默认自营网站，以便默认归属不随当前查看的分类变化。
23. 作为网站管理者，我希望保存后保留当前筛选，并在网站不再符合归属或技术栈条件时收到提示，以便理解网站为何没有显示在列表中。
24. 作为网站管理者，我希望桌面与手机遵循同样的分类及筛选规则，以便在不同设备上使用一致的台账行为。
25. 作为网站管理者，我希望导出按钮明确说明导出全部，以便不会把完整备份误解为当前筛选结果。
26. 作为网站管理者，我希望 JSON 导出、Excel 导出和 JSON 备份导入保留归属信息，以便数据流转与恢复时不丢失分类。
27. 作为网站管理者，我希望旧导入文件没有归属字段时保留已有网站的归属，新导入的网站默认自营，以便兼容旧资料。
28. 作为网站管理者，我希望 AI 同步能够更新明确提供的归属，并在没有提供归属时保留原值，以便同步其他运营资料时不覆盖已维护的分类。

## Implementation Decisions

- **领域维度**：网站归属关系、技术栈、网站类型是三个独立维度。企业客户网站属于归属分类，不作为 WordPress、Astro、Next.js 的替代技术栈值。
- **归属数据**：网站记录增加 `ownership` 字段，合法值为“未分类”“自营网站”“企业客户网站”；新增默认自营网站。未分类使用明确的分类值表达。
- **旧数据升级**：通过版本化数据库升级增加归属字段，使旧网站统一为自营网站，保留原有技术栈、网站类型和其他资料。新数据库直接包含该字段；已有数据库先备份、执行一次对应升级，再发布功能。
- **资料维护**：复用现有新增与编辑表单、网站台账及详情展示。列表只支持逐个修改归属，不增加批量编辑能力。
- **组合筛选**：复用现有网站导航和列表筛选流程，网站归属与技术栈按共同满足的条件取交集。选择全部归属只解除归属限制，选择全部技术栈只解除技术栈限制。
- **导航数量**：技术栈数量按当前归属计算；归属数量按当前技术栈计算。搜索词不影响这两组数量。
- **浏览状态**：归属与技术栈分别记录在浏览地址的 `ownership` 与 `platform` 条件中，支持刷新及浏览历史恢复。桌面侧边导航与手机导航复用同一套分类规则。
- **保存后的列表**：新增始终默认自营网站，不继承当前归属筛选。保存成功后保持筛选；网站不满足当前归属或技术栈条件时不显示在结果中，并提示“已保存，该网站不在当前筛选范围内”。
- **网站概览**：概览接口按归属和技术栈筛选网站数量、到期、SEO、优秀网站及日点击分布。最久未 SEO 的网站先限制范围，再排序截取，不从全局已截取的结果中二次过滤。页面明确展示统计范围，搜索词不改变概览。
- **全局概览**：账号累计收入和基础设施账号、资源及关联网站总量继续使用全局口径并标明全局。账号可能由不同归属或技术栈的网站共享，不能把相关账号全部收入当作当前网站范围的收入，也不自动均摊。
- **接口与数据流转**：复用现有网站创建、完整编辑、局部更新、导入、导出、快照和 AI 同步接口维护归属。JSON 与 Excel 导出始终包含全部数据及归属，不随当前筛选缩小导出范围。
- **兼容规则**：旧文件未提供归属时，更新已有网站不覆盖其原归属，新导入的网站使用自营默认值；AI 同步未提供归属时保留原值。
- **现有实现的防回归约束**：归属保存失败恢复原值；同一网站保存期间限制重复修改归属；较早返回的概览成功或失败响应不能覆盖当前筛选的数据和错误状态。这些是本次仓库实现已有的行为，不扩展为新的业务能力。

## Testing Decisions

用户已确认复用以下两个现有边界，不增加专用测试接口，也不把每个内部组件、辅助函数或查询都拆成独立验收边界。

**测试原则**：通过可观察的页面结果、接口响应和持久化数据验证需求。测试不依赖内部变量名、源码文本、组件层级或具体 SQL 写法。页面测试与接口测试分别证明各自覆盖的行为，不将两者等同于浏览器连接真实线上数据库的完整链路测试。

### 边界一：页面交互

- **被测范围**：新增与编辑表单、网站列表、归属快捷修改、网站详情、桌面及手机导航、概览展示、浏览状态和导出入口。
- **既有先例**：仓库已有 Playwright 浏览器验收，运行真实页面组件，由内存接口数据提供受控场景和成功、失败、延迟响应。
- **分类与维护场景**：验证新增默认自营，可改选其他归属；编辑与详情正确展示；列表逐个修改归属，保存成功后结果符合当前筛选；保存失败恢复原值。
- **筛选场景**：验证全部条件、单独归属、单独技术栈、两者交集及空结果；切换一组保留另一组；导航数量按另一组条件计算；搜索只改变列表。
- **浏览与设备场景**：验证刷新、详情返回、浏览器前进后退恢复两组条件；桌面与手机规则一致。
- **统计与导出场景**：验证网站概览标明当前归属和技术栈范围，全局收入及基础设施明确标为全局；筛选状态下点击导出全部仍生成包含全部归属数据的 Excel。
- **已有保护行为**：同一网站归属保存未结束时不能重复修改；保存失败后可继续操作；快速切换筛选时，旧概览成功或失败响应不覆盖新范围的结果。
- **证据边界**：受控接口能证明页面如何显示、提交和处理响应，不能单独证明服务端的数据写入、统计查询或线上 D1 运行情况。

### 边界二：接口与数据持久化

- **被测范围**：网站资料写入、局部更新、JSON 导入及导出、Excel 快照数据、AI 同步、概览统计和旧库升级。
- **既有先例**：仓库已有接口处理器与 SQLite 集成测试，执行真实处理器和查询，仅适配 D1 的调用方式；原有数据模型测试也使用真实 SQLite 数据库验证升级和约束。
- **数据与独立性场景**：验证三种合法归属、缺省规则以及非法归属拒绝；修改归属不误改技术栈或网站类型；更新结果能从数据库读取。
- **兼容场景**：验证旧网站升级后为自营且原资料保留；旧文件更新已有网站时保留归属，新导入网站默认自营；AI 同步只有明确提供归属时才修改该字段。
- **备份场景**：JSON 导出再导入保留三类归属；JSON 导出和 Excel 快照不因传入筛选条件而漏掉其他网站。
- **统计场景**：用不同归属、不同技术栈和超出截取数量的 SEO 数据验证交集、零匹配及先筛选后排序；搜索词不缩小概览。用共享账号或资源验证全局收入和基础设施总量不因网站筛选而误缩小。
- **证据边界**：SQLite 验证数据及查询行为，不能代替实际线上 Cloudflare D1 的升级执行或运行验收。

现有认证测试、数据模型测试、类型检查、生产构建、Functions 编译与清理检查作为项目回归检查保留。页面边界和数据边界的具体覆盖及运行方式沿用仓库已有测试约定。

## Out of Scope

- 企业名称、联系人、客户档案及按具体企业客户管理网站。
- 同一网站同时选择多个归属。
- 勾选网站后批量修改归属。
- 根据技术栈、网站类型或 AdSense 收益自动推断网站归属。
- 将账号总收入按网站归属或技术栈拆分、均摊。
- 仅导出当前筛选结果。
- 增加网站类型类别或替换现有技术栈分类。

## Further Notes

- 项目统一使用“网站归属关系”“自营网站”“企业客户网站”“未分类”。不使用“企业用户”表示企业客户网站，也不将自营网站误解为只有管理者自己访问的网站。
- 本规格遵循已有两项架构决策：归属独立于技术栈和网站类型；筛选内的网站统计与全局账号统计分开表达。
- 当前仓库已有本地实现与此前验收记录，线上发布和数据库升级尚未执行。本规格发布到事项追踪器，不代表功能已在线上发布，也不要求重复实现已有功能。
- 功能范围来自已确认讨论；保存失败、重复保存和过期响应的行为来自当前实现及已确认回归边界。未将其他潜在需求补为验收条件。
- 用户已确认两个测试边界及工程技能配置草案，指定 GitHub 仓库 `ycdigi/Domain-Manager` Issues 为发布位置。配置已写入，`ready-for-agent` 标签已创建；启用仓库 Issues 时受当前访问令牌的仓库设置权限限制。待 Issues 启用后检索重复事项，再发布本规格并应用该标签。
