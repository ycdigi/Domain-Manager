# 网站维护入口修正

日期：2026-11-26。

## 已实现

- 账号编辑增加默认 GitHub Token，密文存储，留空保留原值。
- 自动迁移账号备注中的纯 GitHub PAT；默认凭据冲突时保留原值并提示。普通列表和便携备份屏蔽此类旧明文备注。
- 网站部署资料支持推送地址、WordPress 完整后台登录地址。现有主要仓库地址可作为推送地址默认来源。
- 操作列按 GitHub、WordPress 后台、配置入口分流；复制使用网站所选账号的 Token 和邮箱，保留用户指定的四行格式。
- 缺失资料提示并打开设置；已有多个直接 GitHub 账号时明确要求选择一个。旧有单站与多选分析复制保持不变。

## 升级顺序

1. 使用管理站所属的 Cloudflare 账号，确认 `domains-db` / `92f8fb6b-9bde-4c9c-a3df-446834e00d8e` 是目标数据库，完整备份。
2. 执行 `schema-migration-v1.29.0.sql`，只增加 `websites.github_push_url`、`websites.wp_login_url`，不重新初始化数据库。先检查字段是否已存在，避免重复执行 ALTER。
3. 核对数据库中原有网站、域名、账号、凭据数量及字段；确认 Functions 环境有现有 `CREDENTIAL_ENCRYPTION_KEY`，不要替换已加密凭据使用的密钥。
4. 发布应用，打开 GitHub 账号页触发旧备注迁移；处理有冲突的账号。为网站填写实际仓库推送地址，必要时设置 WordPress 自定义后台地址。
5. 登录后验证复制及自定义后台跳转。复制按钮仅生成剪贴板文本，不实际执行 Git 推送；登录按钮仅打开地址。

## 验证

Node/SQLite 回归覆盖：准确复制模板、账号优先级、多个账号拒绝、加密存储、空 Token 保留、旧备注迁移与冲突、并发迁移不覆盖默认值、凭据事务回滚、日期与停用状态保留、未授权访问、维护地址校验、便携备份往返和数据库升级。

现有 Playwright 测试设施增加 `tests/website-maintenance-ui.py`：使用隔离 API fixtures，读取实际剪贴板、验证默认与自定义后台链接、缺失邮箱后进入设置，以及维护地址和 Token 表单保存。既有资源界面回归同时运行。此测试不写生产数据。

最新验证：全量 247 项 Node/SQLite 测试通过；`npm run build`、`npm run lint:cleanup`、Pages Functions 编译通过。维护入口 Playwright 回归及既有资源界面回归通过。独立代码审查复核通过。构建仍提示已有的大包体积警告。

## 生产发布记录

2026-11-26 已通过用户授权登录目标 Cloudflare 账号，确认 Pages 项目 `domain-manager` 的生产分支为 `main`，`DB` 绑定目标数据库。先前的账号权限阻塞已解除。

已完整导出生产数据库，并在本地恢复副本通过 SQLite 完整性校验。随后执行 v1.29 迁移，核对两个新增字段存在，原有 142 个网站、142 个域名、7 个服务账号、0 条加密凭据数量不变。

生产环境原先没有 `CREDENTIAL_ENCRYPTION_KEY`，且尚无加密凭据。本次已生成随机密钥，配置为生产环境 Secret。数据库备份与密钥备份保存在被 Git 忽略的本地 `backups/` 目录，文件权限为 0600；密钥不进入代码、文档或日志。后续须保留该密钥，不可随意替换。

应用修正合入 `main` 后由现有 Cloudflare Git 集成触发生产部署；需核对该提交的部署状态，并在登录后验收维护入口。
