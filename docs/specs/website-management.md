# 网站管理、工作登记与 GSC 归属

2026-11-21。GitHub 仓库 Issues 当前关闭，规格及验收记录暂存本文件；未修改仓库设置。

## 功能

- 独立“网站管理”导航与页面，按网站和主域名展示；支持搜索、经营状态、网站批次、四类登记有无、GSC 账号和最近登记排序，条件保存在网址。所有筛选初始不限定范围，显示中文提示；默认包含经营中和停止经营的网站。批次筛选复用既有批次，按当前成员关系匹配，保留已归档批次可查询，排除已移出的成员历史；各条件可单独清除，也可一键重置。
- 四类工作为 TDK 调整、计算器开发、文章开发、样式调整。每次点击登记一次，同一天允许多次，服务端记录 UTC 时间、界面显示上海时间。
- 数字显示有效次数，悬停显示最近时间，点击查看历史。撤销保留作废标记，统计重新计算；同一个请求重试不重复登记，也不恢复已撤销记录。
- 原 `website_operations` 按日期和 SEO／内容／技术分类的历史完整保留，在网站详情“任务与记录”中与新工作登记分别展示，不推断为四类工作。
- GSC 账号由管理者填写名称和可选邮箱。网站初始未关联，每站至多一个账号，一个账号可关联多个网站。名称、邮箱不代替 Google 授权或 `gsc_connected` 状态。已关联账号不得直接删除。
- JSON 备份、恢复与 Excel 覆盖工作登记、作废标记、GSC 账号和关联。Excel 网站管理汇总从同一次备份生成，计数排除作废记录。
- 恢复校验接受历史未填写的指标统计日期，保留原空值；日常新增和修改指标仍须填写日期。无效数量和已填写的无效日期仍拒绝。
- GSC 恢复按邮箱或名称匹配已有账号；二者指向不同账号或多条输入指向同一账号时，预览和导入均在写入前拒绝。

## 迁移与发布

`v1.27.0` 仅新增三张表和索引，可重复执行。新数据库使用完整 `schema.sql`，已有数据库不得重新初始化。

2026-11-21 的生产结构检查发现 `websites.new_site_override` 缺失。该字段已存在于应用和初始化结构中，缺失会导致现有备份失败。执行前使用 `PRAGMA table_info(websites)` 核对；仅缺失时补执行现有 `schema-migration-v1.16.0.sql`，默认空值，不修改网站数据。已具备该列的数据库不得重复运行此旧迁移。

本地演练：

```sh
python3 scripts/rehearse-website-management.py --input backups/完整导出.sql --output backups/新的演练目录
```

脚本对比所有原表原字段值、核对初始化结构、完整性与外键，并向另一空数据库恢复原 SQL。发布前导出生产完整 SQL 并演练，再执行已核对的缺失字段修复及增量迁移，推送代码并发布相同提交的 Pages。此增量迁移不删除原结构，旧 Pages 与监控 Worker 可继续读取。
