# Cloudflare 原生巡检与站内告警

## 状态

已接受（2026-11-12）；同日修订为仅检查 HTTP 响应头，取代原静态正文规则与标题复核决策。

## 决策

现有 Pages 负责管理界面和登录保护 API，独立 Worker 用 Cron 分批巡检，共用 D1。每站默认十二小时一次，每分钟处理一个到期网站；首次失败五分钟后复查，连续两次失败记录事件。检查历史保留三十天。只提供站内提醒。暂停和停止经营的网站不自动巡检。网站监控判断与原有域名可用性分开。

此能力取代原有每六小时 GitHub Actions 的自动检查，保留旧状态接口兼容已有调用。检查使用 HTTPS、严格 2xx 和有限跳转：优先 HEAD，仅在 405 / 501 时回退 GET，获得响应头后取消响应体，不读取正文。配置只有启用开关与允许跳转的主机名，不再扫描关键词、提取标题或判断内容完整性。响应正常仅表示 HTTP 可访问，不表示安全或未被攻击。

后端保留旧字段及历史以兼容备份，旧内容规则不再执行。新检查仅产生 healthy / failure，`title` 为 null，`content_complete` 为 false。旧 review / incomplete 在界面标为“旧检查/待重新检查”，历史内容原因可标为“旧版内容检查”，当前表格不重复显示旧内容警告。

租约防止并发重复检查，主域名或配置改变时拒绝旧结果。监控与 SEO 复查、收入或经营阶段决策相互独立。

## 原因

网站组合需要在不逐站访问的情况下发现 HTTP 访问故障、异常跳转及监控自身停止运行。正文扫描增加 CPU 成本且无法证明内容未被篡改，因此收敛为轻量响应头检查。将巡检放在 Cloudflare 可以沿用现有部署和数据库，避免维护另一套服务器或通知服务。
