# Cloudflare 原生巡检与站内告警

## 状态

已接受（2026-11-12）；同日修订为检查 HTTP 响应、跳转并展示页面标题，取代仅检查响应头的决策；不恢复原静态正文规则与标题复核。

## 决策

现有 Pages 负责管理界面和登录保护 API，独立 Worker 用 Cron 分批巡检，共用 D1。每站默认十二小时一次，每分钟处理一个到期网站；首次失败五分钟后复查，连续两次失败记录事件。检查历史保留三十天。只提供站内提醒。暂停和停止经营的网站不自动巡检。网站监控判断与原有域名可用性分开。

此能力取代原有每六小时 GitHub Actions 的自动检查，保留旧状态接口兼容已有调用。检查使用 HTTPS、严格 2xx 和有限跳转：每一跳使用 GET，每个响应最多读取前 64 KiB HTML，遇到真正的 `</title>`、`</head>` 或 `<body>` 即停止读取并取消剩余响应体，整个检查（含跳转和标题读取）共用十秒超时。标题按响应字符集解码（默认 UTF-8），解码 HTML 实体、折叠空白后最多保留 1000 个字符。配置只有启用开关与允许跳转的主机名，不扫描全文、匹配关键词、保存标题基线或确认标题变化，也不猜测是否为停放页。标题只供人工辅助识别停放或到期页面；响应正常仅表示 HTTP 可访问，不表示安全或未被攻击。

后端保留旧字段及历史以兼容备份，旧内容规则不再执行。新检查仅产生 healthy / failure，`title` 保存获取的页面标题，未获取到时为 null；标题读取错误或响应体过慢不改变已有 HTTP 结果，也不产生“内容检查未完成”状态；`content_complete` 继续为 false。列表、详情和检查历史以纯文本完整换行展示标题，缺失时显示“未获取到标题”。复用已有标题字段，无需数据库迁移。旧 review / incomplete 在界面标为“旧检查/待重新检查”，历史内容原因可标为“旧版内容检查”，当前表格不重复显示旧内容警告。

租约防止并发重复检查，主域名或配置改变时拒绝旧结果。监控与 SEO 复查、收入或经营阶段决策相互独立。

## 原因

网站组合需要在不逐站访问的情况下发现 HTTP 访问故障、异常跳转及监控自身停止运行。仅有 HTTP 200 无法让管理者发现停放或到期页面，因此增加有界 HTML 前缀的标题提取以便人工判断。全文扫描增加 CPU 成本且无法证明内容未被篡改，因此只获取标题，不恢复内容规则。将巡检放在 Cloudflare 可以沿用现有部署和数据库，避免维护另一套服务器或通知服务。
